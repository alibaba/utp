## 用例清单

### A. 结构、引用与原语静态契约

| # | 场景 | 输入 | 预期 |
|---|---|---|---|
| 1 | 目标 Schema JSON 解析 | 56 个目标文件 | 全部可解析 |
| 2 | Draft 2020-12 元 Schema | 56 个目标文件 | 全部通过 `Draft202012Validator.check_schema` |
| 3 | 相对 `$ref` 与 JSON Pointer | 全部目标引用 | 文件和指针均存在，不访问网络 |
| 4 | `$id` 唯一性与协议 | 56 个目标文件 | 全部为唯一 HTTPS URL |
| 5 | 文件与字段说明 | 新增/修改 Schema | 文件有 title/description，业务字段有 description |
| 6 | Action 引用 | Pay/Resolve actions | input/output_schema 均可解析到实体 |
| 7 | 状态迁移引用 | 两个状态机 | from/to 状态存在，Action 名存在且格式合法 |
| 8 | Pay 标准事件 | Pay transitions | PAYMENT_CAPTURED/FAILED 与 PaymentEventType 一致；内部事件显式区分 |

## Mock 策略

| 依赖 | 策略 | 理由 |
|---|---|---|
| 网络与正式 Schema URL | 不访问网络，使用本地 Registry | 保证测试确定性并验证发布包内相对引用 |
| JSON Schema 校验器 | 使用环境已有 Python `jsonschema` 与 `referencing` | 支持 Draft 2020-12，不引入生产依赖 |
| 时间 | 使用固定 RFC 3339 字符串 | 仅验证格式，无需系统时钟 |
| 文档示例 | 直接读取真实 Markdown fenced block | 防止复制一份测试数据后与文档再次漂移 |

## 执行命令

```bash
python3 docs/authoring/tests/pay_resolve_schema_contract_test.py
xmllint --noout docs/assets/diagrams/pay-state-machine.svg docs/assets/diagrams/resolve-state-machine.svg
node --test docs/authoring/tests/*.test.mjs
git diff --check
```

## 不测的内容

- PaymentProcessor、支付渠道、Arbiter 和全局状态机的真实运行时行为。
- 跨字段 decimal 加法、币种换算、责任比例求和等必须由实现方执行的数值算法；测试只确认这些 MUST 约束已在原语说明中声明。
- Source、Negotiate、Purchase、Fulfill 的既有独立 Schema 正确性。
- SVG 的像素级视觉回归；仅验证 XML 合法性和关键状态文本存在。
